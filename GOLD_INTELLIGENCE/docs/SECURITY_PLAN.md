## 1. المبادئ

| المبدأ | التطبيق |
|---|---|
| Least Privilege | كل مكوّن بصلاحية أدنى ضرورية |
| No Secrets in Code | أسرار في Environment/Secret Manager فقط |
| Defense in Depth | طبقات تحقق متعددة (API → Domain → DB) |
| Fail Secure | الفشل يُغلق لا يفتح |
| Audit Everything | كل فعل كتابة مسجّل |
| Zero Trust للـ Input | كل مدخل يُتحقق منه |
| لا كشف للأسرار للمتصفح | كل اتصال بالمزوّد من الـ Backend |

## 2. إدارة الأسرار (Secret Management)

| القاعدة | التفصيل |
|---|---|
| لا مفاتيح في Git | `.gitignore` + فحص pre-commit + secret scanning |
| لا مفاتيح في الواجهة | لا `VITE_*` أو `NEXT_PUBLIC_*` لمفاتيح المزوّدين |
| متغيرات بيئة فقط | تُحمّل عند التشغيل من Secret Manager |
| تدوير دوري | تدوير مفاتيح المزوّدين كل 90 يومًا |
| فصل البيئات | مفاتيح مختلفة لـ dev/staging/prod |
| سجل الوصول | تسجيل من قرأ أي سر (عند توفّر Secret Manager) |

**الأسرار الحسّاسة في هذا المنتج:**
- مفاتيح مزوّد بيانات السوق (الأخطر — تكلّف مالًا وتُعرّض الترخيص للخطر).
- مفاتيح مزوّد AI.
- بيانات اعتماد قاعدة البيانات.
- `OPERATOR_TOKEN` (للأدوات التشغيلية).
- مفتاح توقيع الجلسات (Session Signing Key).

## 3. المصادقة والترخيص (AuthN/AuthZ)

### 3.1 الأدوار

| الدور | الصلاحيات |
|---|---|
| `visitor` | قراءة عامة (سيناريوهات، سجل، موجز) — **بلا** أدوات تفاعلية |
| `user` | كل ما سبق + متابعة محاكاة + مساعد AI |
| `operator` | كل ما سبق + نشر/إلغاء + تفعيل قواعد (يتطلب `OPERATOR_TOKEN`) |
| `service` | مهام داخلية فقط (Jobs) |

### 3.2 القواعد

1. مسارات القراءة العامة: بلا مصادقة، لكن **بـ rate limit**.
2. مسارات الكتابة: مصادقة + ترخيص + token للعمليات الحسّاسة.
3. لا وصول لأي مسار تشغيلي من المتصفح العام.
4. الجلسات: HttpOnly + Secure + SameSite=Lax.
5. انتهاء الجلسة + إبطال صريح عند تسجيل الخروج.

## 4. حماية سجلات السيناريو (Integrity)

**الخطر:** تعديل غير مصرّح به لسيناريو أو نتيجة (لتجميل الأداء).

| الضمانة | التنفيذ |
|---|---|
| Append-only | `scenario_outcomes` و`audit_log` بلا UPDATE/DELETE |
| DB Roles | دور التطبيق بلا صلاحية UPDATE على جداول الحقيقة التاريخية |
| Audit قبل/بعد | `before_state`/`after_state` في كل تغيير |
| سبب إلزامي | لا انتقال بلا `reason` غير فارغ |
| Hash Chain (اختياري) | سلسلة hash على `scenario_status_history` لكشف أي تلاعب |
| مراجعة دورية | تقرير شهري لأي تعديل غير متوقع |

## 5. حماية طبقة AI

| الخطر | الضمانة |
|---|---|
| كتابة AI في جداول الحقيقة | دور DB للـ AI بـ SELECT فقط على جداول الحقيقة |
| تسرّب بيانات في Prompt | لا أسرار، لا بيانات مستخدم شخصية في الـ Prompt |
| اختلاق أرقام | Grounding Check حتمي قبل العرض |
| Prompt Injection | فصل صارم بين تعليمات النظام ومدخل المستخدم |
| تجاوز التكلفة | سقف + Cost Ledger + تنبيه |

## 6. حماية الـ API

| الضمانة | التنفيذ |
|---|---|
| Rate Limiting | لكل IP + لكل مستخدم + لكل endpoint (Redis) |
| Input Validation | Pydantic Schema على كل مدخل، رفض صريح |
| Output Encoding | لا HTML خام من المدخلات |
| CORS | قائمة أصول مسموحة صريحة فقط |
| Timeouts | لكل نداء خارجي (Provider/AI) |
| Circuit Breaker | على نداءات المزوّدين |
| Payload Limits | حد لحجم الطلب |
| لا معلومات حسّاسة في الأخطاء | رسائل عامة للمستخدم، تفاصيل في اللوج |

## 7. حماية قاعدة البيانات

| الضمانة | التنفيذ |
|---|---|
| لا وصول عام | DB في شبكة داخلية، بلا منفذ عام |
| اتصال مشفّر | TLS إلزامي |
| أدوار منفصلة | App (read/write محدود)، AI (read-only)، Migration (owner) |
| Prepared Statements | منع SQL Injection |
| نسخ احتياطي مشفّر | At-rest encryption |
| فحص استعادة | اختبار استعادة دوري |

## 8. التسجيل والمراقبة (Audit & Observability)

**يُسجَّل إلزاميًا:**

- كل تسجيل دخول/خروج ونشاط مصادقة.
- كل فعل كتابة (actor، action، entity، before/after، reason، timestamp).
- كل انتقال حالة سيناريو.
- كل نشر/إلغاء تشغيلي.
- كل فشل تحقق بيانات.
- كل استدعاء AI (المهمة، النموذج، التكلفة).
- كل تجاوز rate limit.
- كل فشل مصادقة/ترخيص.

**يُراقَب (Monitoring):**

| المقياس | التنبيه عند |
|---|---|
| عمر آخر شمعة | تجاوز العتبة لكل إطار |
| معدل فشل التحقق | > 1% من الشموع |
| فشل المزوّد | أي فشل متتالٍ |
| زمن استجابة API p95 | > 400ms |
| تكلفة AI اليومية | > السقف اليومي |
| فشل Jobs | أي فشل متكرر |
| معدل 4xx/5xx | ارتفاع غير طبيعي |

## 10. الأمان من البداية (Checklist للمراحل)

| المرحلة | البنود الإلزامية |
|---|---|
| M1 (Data) | لا مفاتيح في الكود، فحص المدخلات، Circuit breaker |
| M2 (Domain) | Append-only، DB roles، Idempotency |
| M3 (AI) | Read-only DB role، Grounding check، Cost cap |
| M4 (API) | AuthN/AuthZ، Rate limit، CORS، Validation |
| M5 (UI) | لا أسرار في الـ bundle، CSP، لا HTML خام |
| M6 (Ops) | Backup مشفّر، Monitoring، Audit، Secret rotation |
| قبل الإطلاق | فحص اختراق أساسي + مراجعة قانونية |

## 11. مسؤوليات الإفصاح

1. **قبل أول متابعة:** إقرار مخاطر إلزامي (`risk_ack_at`).
2. **في كل مكان يظهر فيه درجة:** «الدرجة ترتيب داخلي، ليست احتمالًا».
3. **في كل إخراج AI:** «تفسير مُولَّد».
4. **في السجل:** «النتائج محاكاة ولا تمثل أداءً حقيقياً».
5. **سياسة خصوصية** توضح ما يُجمع ولماذا.
