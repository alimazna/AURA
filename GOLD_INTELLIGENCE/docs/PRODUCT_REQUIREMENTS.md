## 1. مبادئ التصميم الحاكمة

| المبدأ | التطبيق العملي |
|---|---|
| مصدر حقيقة واحد | الـ Backend يملك السيناريو ودورته وحساباته؛ AI يفسّر فقط |
| الفصل بين المؤكد والمُفسَّر | كل قيمة لها وسم: `VERIFIED_DATA` أو `AI_INTERPRETATION` |
| الصدق عند النقص | `UNAVAILABLE` / `STALE` / `INSUFFICIENT_DATA` بدل التخمين |
| قابلية التدقيق | كل قرار (نشر/تفعيل/إبطال/إلغاء) له سبب ووقت ومصدر وإصدار قواعد |
| عدم التكرار | منع تكرار السيناريو لنفس الفرصة (Idempotency) |
| لا Look-ahead | لا يُقيَّم سيناريو بشمعة أُغلقت قبل إنشائه |

## 2. الكيانات الأساسية للمنتج

### 2.1 السيناريو (Scenario)

الحقول الإلزامية عند النشر:

| الحقل | النوع | إلزامي | ملاحظة |
|---|---|---|---|
| `scenario_id` | string (ULID) | نعم | فريد، ثابت مدى الحياة |
| `published_at` | timestamp (UTC) | نعم | وقت النشر |
| `instrument` | enum | نعم | `XAUUSD` فقط |
| `direction` | enum | نعم | `BUY` / `SELL` |
| `entry_price` أو `entry_zone` | decimal | نعم | سعر أو نطاق |
| `stop_loss` | decimal | نعم | |
| `take_profit_1` | decimal | نعم | |
| `take_profit_2` | decimal | اختياري | |
| `risk_reward` | decimal | نعم | محسوب، لا مُدخل يدويًا |
| `rationale` | text | نعم | سبب السيناريو |
| `evidence_ids[]` | string[] | نعم | مراجع سجلات الأدلة |
| `activation_conditions` | structured | نعم | شروط التفعيل |
| `invalidation_conditions` | structured | نعم | شروط الإبطال |
| `expiration_conditions` | structured | نعم | شرط/مدة الانتهاء |
| `status` | enum | نعم | الحالة الحالية |
| `market_context_id` | string | نعم | لقطة السياق المرجعية |
| `rule_version` | string | نعم | إصدار قواعد المحرك |

### 2.2 الدليل (Evidence)

| الحقل | النوع | ملاحظة |
|---|---|---|
| `evidence_id` | string | فريد |
| `scenario_id` | string | مرجع |
| `kind` | enum | `SUPPORTING` / `CONTRADICTING` |
| `category` | enum | `MARKET_STRUCTURE` / `TECHNICAL` / `EVENT` / `LIQUIDITY` / `MACRO` |
| `description` | text | وصف الدليل |
| `data_refs[]` | string[] | مراجع بيانات (candle_id / event_id) |
| `observed_at` | timestamp (UTC) | وقت ملاحظة الدليل |
| `freshness` | enum | `FRESH` / `AGING` / `STALE` |
| `quality` | enum | `VERIFIED` / `DEGRADED` / `UNVERIFIED` |

**قاعدة إلزامية:** لا يُنشر سيناريو بدون دليل واحد على الأقل من نوع `SUPPORTING`، ويُسجَّل
الدليل المعارض إن وُجد. لا يُنشأ سيناريو لمجرد أن مؤشرًا أعطى إشارة.

### 2.3 لقطة سياق السوق (Market Context Snapshot)

تلتقط حالة السوق **عند** قرار النشر: بنية الأطر العليا، الاتجاه، التقلب، النظام (Regime)،
السيولة، الجلسات، سياق الدولار، توقعات الفائدة، والأحداث القادمة. تُخزَّن كما هي **بلا تعديل
لاحق** — لأنها دليل على ما كان النظام يعرفه لحظة القرار.

### 2.4 نتيجة السيناريو (Scenario Outcome)

تُكتب مرة واحدة عند الإغلاق: الحالة النهائية، السعر النهائي، وقت الإغلاق، السبب، R المحقق،
والتكاليف المحتسبة (سبريد/انزلاق إن أمكن إثباتها). **لا تُعدَّل بعد الكتابة** (Append-only).

## 3. الركائز التسع — المتطلبات التفصيلية

### PILLAR 1 — Gold Context Intelligence

**الغرض:** فهم السياق الأوسع لسوق الذهب والتمييز بين حركة السعر قصيرة الأجل والسياق الأوسع.

**المتطلبات:**

1. تحديد بنية السوق على الأطر العليا (H4/D1/W1): اتجاه، قمم/قيعان أعلى أو أدنى.
2. قياس التقلب (Volatility) بمقياس مُعلن (مثل ATR) ومقارنته بتاريخ مرجعي.
3. تصنيف النظام (Regime): Trending / Ranging / Expansion / Contraction / Event-driven.
4. تقييم السيولة (Liquidity conditions): جلسات، أوقات هادئة، توسّع السبريد.
5. تحديد الدعم والمقاومة المهمة من نقاط تلامس متعددة.
6. سياق الدولار الأمريكي (DXY أو ما يعادله) — كعلاقة ارتباط معلنة لا كسبب وحيد.
7. سياق الفائدة (Interest-rate expectations) وسياق الاقتصاد الكلي.
8. ربط الأحداث الاقتصادية القادمة ضمن نافذة زمنية.
9. **التمييز الصريح** بين «حركة السعر الآن» و«السياق الأوسع» في الواجهة.

**معيار القبول:** كل عنصر سياق له مصدر بيانات وتوقيت، ويُعلن `UNAVAILABLE` عند غيابه.

### PILLAR 2 — Evidence Intelligence

**الغرض:** كل سيناريو له تفسير تحليلي قابل للتتبع.

**المتطلبات:**

1. تسجيل الأدلة الداعمة والمعارضة معًا.
2. تسجيل البنية السوقية والملاحظات الفنية والسياق الحدثي.
3. تتبع حداثة الدليل (freshness) وجودة البيانات (quality).
4. تسجيل سبب قبول الفرصة أو رفضها **بصراحة**.
5. منع النشر عند غياب أدلة كافية — وإرجاع `NO_VALID_OPPORTUNITY` مع السبب.
6. عدم إنشاء سيناريو بناءً على إشارة مؤشر منفردة.

**معيار القبول:** لا يوجد سيناريو منشور بلا `evidence_ids` غير فارغة، ولا `rationale` فارغ.

### PILLAR 3 — Public Proof Ledger

**الغرض:** نظام شفافية وأداء تاريخي يمنع Survivorship Bias.

**المتطلبات:**

1. حفظ السيناريو الأصلي كما نُشر، ثم تاريخه اللاحق كسلسلة أحداث منفصلة.
2. عرض إحصاءات منفصلة: إجمالي المنشور، المفعّل، غير المفعّل، الملغى، المنتهي، الرابح،
   الخاسر.
3. عرض الأداء حسب الفترة الزمنية وحسب فئة السيناريو.
4. **تعريف المقام (denominator) والمنهجية** مع أي نسبة نجاح معروضة.
5. عدم حذف أي سيناريو — بضمن ذلك الخاسر والملغى والمنتهي وغير المفعّل.
6. تمييز إحصاءات «السيناريوهات المفعّلة» عن «كل السيناريوهات المنشورة».

**معيار القبول:** لا تُعرض نسبة نجاح بدون مقام معلن. الرقم الكلي = مجموع كل الفئات.

### PILLAR 4 — Scenario Intelligence

**الغرض:** محرك التحليل الذي ينشئ ويقيّم ويرصد سيناريوهات XAUUSD.

**المتطلبات:**

1. التعرّف على فرص محتملة من السياق والأدلة.
2. تقييم السياق والأدلة الداعمة والمعارضة.
3. تحديد شروط دخول صحيحة (سعر أو نطاق أو حدث).
4. تعريف شروط الإبطال والإلغاء.
5. حساب R/R بشكل حتمي من الأسعار (لا إدخال يدوي).
6. تقييم قوة الفرصة بما يكفي للنشر — **مع السماح الصريح بـ NO VALID OPPORTUNITY**.
7. رصد السيناريو بعد النشر وانتقالات الحالة.
8. منع التكرار والتقاطع بين السيناريوهات (deduplication).

**معيار القبول:** المحرك قادر على إرجاع «لا فرصة» بنجاح مُختبَر، لا كحالة استثنائية.

### PILLAR 5 — Gold Event Reaction Lab

**الغرض:** فهم تأثير الأحداث الاقتصادية المهمة على الذهب.

**المتطلبات:**

1. تتبع قرارات الفيدرالي، التضخم، الوظائف، الفائدة، البيانات الأمريكية المهمة.
2. التمييز بين الأحداث المجدولة وغير المتوقعة.
3. تسجيل **التفاعل الفعلي** للسعر لا التأثير المفترض.
4. بناء سجل تاريخي للتفاعل (Event Reaction Records) قابل للبحث.

**معيار القبول:** لا يُسجَّل تفاعل حدث بلا مرجع سعري موثّق قبل/بعد الحدث.
**تبعية:** يحتاج مزوّد تقويم اقتصادي (فجوة بيانات موثقة في RESEARCH_LOG §3).

### PILLAR 6 — Gold Replay Intelligence

**الغرض:** دراسة ظروف سوق تاريخية بلا Look-ahead Bias.

**المتطلبات:**

1. إعادة تشغيل تاريخية للشارت.
2. إعادة بناء السيناريو كما كان سيعرف في لحظته.
3. مراجعة البنية السوقية التاريخية والأدلة.
4. مقارنة التحليل الأصلي مع سلوك السوق اللاحق.
5. **حظر صريح** لأي معلومة لم تكن متاحة عند توقيت التحليل التاريخي.

**معيار القبول:** اختبار انحدار يثبت أن أي تقييم تاريخي لا يستخدم شمعة أُغلقت بعد نقطة القرار.
**ملاحظة:** مرحلة متأخرة، لكن تصميم قاعدة البيانات يجب أن يسمح بها من الآن.

### PILLAR 7 — Personal Gold AI Assistant

**الغرض:** مساعد ذكي متخصص في XAUUSD.

**المتطلبات:**

1. شرح ظروف السوق الحالية من بيانات معتمدة.
2. شرح السيناريوهات المنشورة (الدخول، SL، TP، المخاطرة).
3. شرح سبب نشر سيناريو / إلغائه / عدم وجود فرصة.
4. تبسيط المفاهيم للمبتدئين.
5. الوصول إلى بيانات المنتج المعتمدة والأدلة فقط.
6. **التمييز الصريح** بين البيانات المتحقق منها والتفسير وعدم اليقين.
7. **منع صريح** لاختلاق أي معلومة سوق حالية.

**معيار القبول:** عند سؤال المساعد عن سعر غير موجود في البيانات المعتمدة، يجيب «غير متاح»
ولا يخترع رقمًا. (اختبار إلزامي).

### PILLAR 8 — Personal Performance Coach

**الغرض:** نظام تعليمي/تحليلي لسلوك المستخدم في متابعة السيناريوهات.

**المتطلبات (مرحلة متأخرة):**

1. تحليل سلوك متابعة السيناريوهات المحاكاة.
2. تحديد الأخطاء الشائعة.
3. تعليم مفاهيم إدارة المخاطر.
4. قياس التقدم التعليمي.
5. التمييز بين القرار المنضبط والاندفاعي.
6. **إعلان صريح** أن النتائج المحاكاة لا تمثل أداءً حقيقيًا.

**التبعية:** يحتاج بيانات سلوك مستخدم حقيقية + موافقة خصوصية.

### PILLAR 9 — Gold Daily Brief

**الغرض:** موجز يومي منظم لسوق الذهب.

**المتطلبات:**

1. السياق العام للسوق.
2. الدعم والمقاومة المهمة.
3. الأحداث الاقتصادية ذات الصلة.
4. التقلب والنظام الحالي.
5. التغييرات المهمة في البنية السوقية.
6. السيناريوهات المنشورة.
7. المخاطر وعدم اليقين.
8. الشروط التي قد تُبطل الرؤية الحالية.

**معيار القبول:** كل بند في الموجز يعتمد على دليل مسجّل وبيانات متحقق منها.

## 5. دورة حياة السيناريو — النموذج الكامل

### 5.1 الحالات

| الحالة | المعنى | هل هي نهائية؟ |
|---|---|---|
| `PUBLISHED` | نُشر السيناريو للتو، لم يدخل السعر منطقة الدخول | لا |
| `WAITING_FOR_ACTIVATION` | السعر لم يصل بعد لشرط التفعيل؛ الرصد نشط | لا |
| `ACTIVATED` | تحقق شرط الدخول فعليًا؛ بدأ الرصد نحو TP/SL | لا |
| `PARTIALLY_COMPLETED` | تحقق TP1 ولم يتحقق TP2 بعد | لا |
| `TARGET_REACHED` | تحقق الهدف النهائي | **نعم** |
| `STOP_LOSS_REACHED` | تحقق وقف الخسارة | **نعم** |
| `CANCELLED` | أُلغي بقرار قبل التفعيل (ظرف جديد) | **نعم** |
| `EXPIRED` | انتهت صلاحية السيناريو زمنيًا بلا تفعيل | **نعم** |
| `INVALIDATED` | تحقق شرط إبطال قبل التفعيل | **نعم** |
| `NOT_ACTIVATED` | لم يتحقق شرط التفعيل خلال الأفق الزمني | **نعم** |

### 5.3 الحالات الحدّية (Edge Cases) — تحليل إلزامي قبل التثبيت

هذا هو الجزء الذي طلب الطلب عدم تثبيت الآلة قبله. الحالات الحدّية المُحدَّدة:

| # | الحالة الحدّية | القرار المقترح |
|---|---|---|
| EC-1 | السعر تحرّك في الاتجاه المتوقع **قبل** التفعيل ثم عاد | يبقى `WAITING_FOR_ACTIVATION`. **لا يُعدّ نجاحًا.** |
| EC-2 | السعر لامس منطقة الدخول ووصل TP في نفس الشمعة | `ACTIVATED` ثم `TARGET_REACHED` مع تسجيل أن الشمعة واحدة |
| EC-3 | السعر لامس منطقة الدخول ووصل SL في نفس الشمعة | `ACTIVATED` ثم `STOP_LOSS_REACHED`. **يُعد خسارة** (الافتراض المتحفظ) |
| EC-4 | السعر لامس SL و TP في نفس الشمعة معًا | الافتراض المتحفظ: **SL أولًا** (أسوأ حالة) |
| EC-5 | انقطاع بيانات أثناء سيناريو مفعّل | تجميد الرصد، حالة `DATA_INTERRUPTED` معلنة، **لا تأكيدات جديدة** |
| EC-6 | شمعة ناقصة/غير مكتملة عند نقطة التفعيل | لا تفعيل حتى إغلاق الشمعة |
| EC-7 | فجوة سعرية (Gap) عبرت SL | يُنفّذ عند سعر الفتح (أسوأ من SL) ويُسجَّل الانزلاق |
| EC-8 | فجوة سعرية عبرت TP | يُحقَّق الهدف عند سعر الفتح (أفضل من TP) ويُسجَّل |
| EC-9 | حدث اقتصادي مفاجئ أثناء سيناريو | يُقيَّم وفق شروط الإبطال إن وُجدت؛ لا تدخّل بشري غير موثّق |
| EC-10 | سيناريوهان متعاكسان على نفس المنطقة | يُرفض الثاني (منع التقاطع) أو يُدمج مع سبب معلن |
| EC-11 | تعديل المزوّد لشمعة تاريخية (Repaint) | يُسجَّل التغيير؛ النتيجة الأصلية **لا تُعدَّل** (Audit) |
| EC-12 | انتهاء الأفق الزمني والسعر داخل منطقة الدخول | `EXPIRED` وليس `NOT_ACTIVATED` — التمييز مهم للإحصاء |
| EC-13 | تحقق شرط الإبطال وشرط التفعيل في نفس اللحظة | أولوية الإبطال (متحفظ) مع تسجيل التعارض |
| EC-14 | تعطّل نظام الرصد ساعات | يُعلن `MONITORING_GAP`، وتُحسب النتيجة من الشموع الفعلية إن أمكن |
| EC-15 | طلب المستخدم «متابعة» سيناريو منتهٍ | مسموح كسجل فقط، لا كفرصة جديدة |

**قاعدة عامة:** في كل تعارض، يُختار **الافتراض المتحفظ** (الأسوأ) لتفادي تضخيم الأداء.

## 6. وضع التعليم للمبتدئين

مفاهيم تُشرح داخل التطبيق (شرح سياقي موجز، لا روابط خارجية إجبارية):

1. ما هو سعر الدخول (Entry Price)؟
2. ما هو وقف الخسارة (Stop Loss)؟
3. ما هي أهداف الربح (Take Profit)؟
4. ما هي نسبة المخاطرة/المكافأة (Risk/Reward)؟
5. ما هو الشراء (BUY)؟ وما هو البيع (SELL)؟
6. لماذا قد لا يُفعَّل سيناريو أبدًا؟
7. لماذا قد يخسر سيناريو بُني منطقيًا؟
8. ماذا يعني كل حالة سيناريو؟
9. ما هو الإبطال (Invalidation)؟
10. لماذا الانتظار أفضل أحيانًا من الدخول؟

**قبل أول متابعة سيناريو:** عرض مقدمة مخاطر واضحة تُبيّن أن الذهب والتداول بالرافعة قد
يؤديان إلى خسائر مالية سريعة، وأن متابعة السيناريوهات المحاكاة **لا تُثبت** ملاءمة التداول
الحقيقي.
