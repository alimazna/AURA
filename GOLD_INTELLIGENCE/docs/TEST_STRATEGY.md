# TEST_STRATEGY.md — استراتيجية الاختبار

> **المستند 16 من 17** | الحالة: مسودة | آخر تحديث: 2026-11-14
> **قاعدة حاكمة:** لا يُعلن نجاح اختبار لم يُنفَّذ. لا نتائج مُختلقة.

## 1. هرم الاختبار

```
                    ┌──────────────┐
                    │  E2E (قليل)  │  ← تدفق كامل: بيانات → سيناريو → رصد → سجل
                    └──────────────┘
                 ┌────────────────────┐
                 │ Integration (متوسط)│  ← حدود الوحدات + DB + مزوّدون مُحاكَون
                 └────────────────────┘
            ┌──────────────────────────────┐
            │   Unit (كثير — الأساس)       │  ← حتمية، آلة الحالة، تحقق، حساب
            └──────────────────────────────┘
```

**الأولوية:** الطبقة الحتمية (Unit) هي الأثقل — لأنها مصدر الحقيقة.

## 2. مبادئ الاختبار

| المبدأ | التطبيق |
|---|---|
| اختبار الكود الحقيقي | تجنّب الـ mocks إلا لضرورة مبرَّرة (المزوّد الخارجي/AI) |
| الحتمية أولًا | كل منطق حالة/حساب يُختبر بلا شبكة |
| اختبار الحالات الحدّية | كل EC-1..EC-15 لها اختبار |
| اختبار الفشل | كل مسار فشل مُختبر (لا اختبار المسار السعيد فقط) |
| لا Look-ahead | اختبار انحدار إلزامي |
| دليل قابل للتكرار | كل اختبار يعمل بـ seed ثابت |

| TC-L12 | EC-7: فجوة عبر SL → سعر الفتح |
| TC-L13 | EC-8: فجوة عبر TP → سعر الفتح |

## 4. اختبار الانحدار الحرجة (Regression Guards)

| # | الحارس | لماذا حرج |
|---|---|---|
| RG-01 | **لا Look-ahead** | يمنع أداء مُضخَّم كاذب |
| RG-02 | **لا حذف سيناريو** | يمنع Survivorship Bias |
| RG-03 | **Append-only outcomes** | يمنع تعديل التاريخ |
| RG-04 | **Grounding check للـ AI** | يمنع اختلاق الأرقام |
| RG-05 | **الشمعة المكتملة فقط للتأكيد** | يمنع تأكيدًا غير ثابت |
| RG-06 | **لا مسار تنفيذ حقيقي** | يمنع تحوّل المنتج لمنصة تنفيذ |

## 5. بيئات الاختبار

| البيئة | الغرض | البيانات |
|---|---|---|
| Unit | منطق حتمي | بيانات مُصنَّعة **موسومة بوضوح** كاختبارية |
| Integration | حدود + DB | DB اختبارية + مزوّد مُحاكَون |
| Staging | تدفق كامل | بيانات حقيقية (بيئة منفصلة) |
| Production | مراقبة | بيانات حقيقية |

**قاعدة صارمة:** أي بيانات مُصنَّعة للاختبار **تُوسم صراحة** ولا تدخل أي إحصاء أداء.
(هذا مبدأ موجود في المشروع المرجعي، ونتبنّاه.)

## 8. معالجة الفشل في الاختبار

- لا يُعلن نجاح مع فشل.
- لا تُعطَّل اختبارات لتُمرَّر التغييرات.
- أي اختبار فاشل = العمل غير مكتمل (يُترك `in_progress` لا `done`).
- أي خطأ متكرر يستدعي تحليل السبب الجذري (5-7 فرضيات) قبل الإصلاح.
