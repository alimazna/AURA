### 2.2 قواعد إلزامية

1. **التمييز الصريح** بين «منشور» و«مفعّل» في كل بطاقة وكل لوحة.
2. عند غياب فرصة: رسالة «لا توجد فرصة صالحة اليوم» + سبب موجز + سياق السوق. **لا** فرصة
   مصطنعة.
3. كل رقم له مصدر وتوقيت عند المرور/التوسيع.
4. «لماذا؟» يفتح: مبتدئ (افتراضي) → احترافي (قابل للتوسيع) — تنفيذ DECISION B.
5. شريط جودة البيانات ظاهر دائمًا أعلى الشاشة.
6. **قبل أول متابعة:** `RiskBanner` إلزامي (مقدمة المخاطر).
7. زر «متابعة (محاكاة)» — النص يذكر «محاكاة» صراحة، **لا** كلمة «تنفيذ».

### 2.3 حالات الشاشة

| الحالة | العرض |
|---|---|
| فرص موجودة | شارت + لوحة السيناريو النشط + قائمة |
| لا فرص | رسالة صادقة + سياق + «لماذا لا توجد فرصة؟» |
| بيانات قديمة | شريط تحذير + تعطيل أزرار المتابعة |
| بيانات غير متاحة | رسالة «غير متاح» + لا شارت كاذب |
| حدث اقتصادي وشيك | شريط تنبيه + تحذير من التقلب |

## 3. Scenario Detail — تفاصيل السيناريو

**الغرض:** الفهم الكامل لسيناريو واحد.

| القسم | المحتوى |
|---|---|
| Header | ID، وقت النشر، الحالة، الاتجاه |
| المستويات | الدخول/المنطقة، SL، TP1، TP2، R/R (محسوب) |
| السياق | لقطة سياق السوق عند النشر (UTC) |
| الأدلة | داعم + معارض، مع حداثة وجودة كل دليل |
| الشروط | التفعيل، الإبطال، الانتهاء |
| الشرح | مبتدئ (افتراضي) + احترافي (قابل للتوسيع) |
| الجدول الزمني | كل انتقال حالة مع السبب والتوقيت |
| الحالة الآن | السعر الحالي + آخر تحديث + حالة البيانات |
| الأحداث | أحداث اقتصادية ذات صلة |

**قاعدة:** لا يُعدَّل أي حقل أصلي. التحديثات تظهر في الجدول الزمني فقط.

## 4. My Previous Trades — صفقاتي السابقة

**الغرض:** سجل متابعة المستخدم (محاكاة).

| المنطقة | المحتوى |
|---|---|
| Filter Bar | الفترة، الحالة، الاتجاه، النتيجة |
| List | كل سيناريو تابعه المستخدم + النتيجة + الفرق عن عدم المتابعة |
| Summary | إحصاءات المستخدم المحاكاة (مع تنبيه أنها ليست أداءً حقيقيًا) |
| Insight | «سلوكك: تتابع غالبًا عند التقلب العالي» (لاحقًا — PILLAR 8) |

**تحذير إلزامي:** «النتائج محاكاة ولا تمثل أداءً تداولياً حقيقياً.»

## 5. Market Analysis — تحليل السوق

**الغرض:** السياق الأوسع للذهب (PILLAR 1).

| القسم | المحتوى |
|---|---|
| Structure | بنية H4/D1/W1: اتجاه، قمم/قيعان |
| Trend vs Movement | **تمييز صريح** بين حركة السعر الآن والسياق الأوسع |
| Volatility | ATR وقيم مقارنة + تصنيف |
| Regime | Trending / Ranging / Expansion / Contraction / Event |
| Liquidity | مناطق السيولة، أوقات هادئة، السبريد |
| Levels | دعم/مقاومة من نقاط تلامس متعددة |
| USD Context | DXY أو ما يعادله (كعلاقة معلنة) |
| Rates | توقعات الفائدة |
| Events | أحداث قادمة في نافذة زمنية |

**قاعدة:** كل عنصر يحمل مصدره وتوقيته أو `UNAVAILABLE`.

## 6. News & Economy — الأخبار والاقتصاد

**الغرض:** الأحداث والتقويم (PILLAR 5).

| المنطقة | المحتوى |
|---|---|
| Calendar | تقويم: وقت (UTC + محلي)، الدولة، الأهمية، الفعلي/المتوقع/السابق |
| Filters | الأهمية، الدولة، الفئة |
| Event Detail | التفاعل الفعلي للسعر (PILLAR 5) — لا التأثير المفترض |

| Unexpected | الأحداث غير المتوقعة مُوسمة صراحة |

**قاعدة:** لا يُسجَّل تفاعل حدث بلا مرجع سعري قبل/بعد.

## 7. Gold AI Assistant — مساعد الذهب

**الغرض:** أسئلة المستخدم عن السوق والسيناريوهات (PILLAR 7).

| المنطقة | المحتوى |
|---|---|
| Chat | محادثة عربية |
| Context Chip | «يعتمد على: بيانات السوق المعتمدة + السيناريوهات المنشورة» |
| Answer Card | الإجابة + **مراجع البيانات** لكل رقم + وسم «تفسير مُولَّد» |
| Suggested | أسئلة جاهزة: «اشرح السيناريو الحالي»، «لماذا لا توجد فرصة؟» |
| Uncertainty | عند عدم اليقين: وسم واضح «غير مؤكد» |

**قواعد:**
1. لا يخترع أي معلومة سوق — يجيب «غير متاح» عند غياب البيانات.
2. كل رقم في الإجابة له مرجع مرئي.
3. لا صيغة توصية شخصية.
4. عند فشل التحقق (Grounding) → «الشرح غير متاح حاليًا».

## 8. Education & Performance — التعليم والأداء

**الغرض:** تعليم المبتدئين + أداء المنتج الشفاف.

### 8.1 Education

المفاهيم العشرة (راجع `PRODUCT_REQUIREMENTS.md` §6) كبطاقات قصيرة + مثال مرئي على شارت.
**شرح سياقي** لا إحالة خارجية إجبارية.

### 8.2 Public Performance Ledger (PILLAR 3)

| المنطقة | المحتوى |
|---|---|
| Definitions | **المقام والمنهجية معلنان أعلى الجدول** |
| Breakdown | إجمالي المنشور، المفعّل، غير المفعّل، الملغى، المنتهي، الرابح، الخاسر |
| Time Filter | حسب الفترة |
| Category Filter | حسب الفئة/الإطار/الاتجاه |
| Methodology Link | «كيف نحسب الأداء؟» بجوار الجدول مباشرة |

**قواعد:**
1. لا نسبة نجاح بلا مقام معلن.
2. المجموع = مجموع كل الفئات (تحقق حسابي معروض).
3. السيناريوهات الخاسرة والملغاة وغير المفعّلة ظاهرة دائمًا.
4. لا عرض احتمالية أو دقة متوقعة.

## 12. تقييم البنية المقترحة (مطلوب في الطلب)

**البنية المقترحة من المالك:** Home, Ready Trades, My Previous Trades, Market Analysis,
News & Economy, Gold AI Assistant, Education & Performance, Account & Settings.

**التقييم:** البنية **جيدة ومنطقية** — تضع Ready Trades في المرتبة الثانية (مباشرة بعد
الرئيسية) وهو صحيح لمنتج يركز على الفرص. التعديلات المقترحة:

| # | الملاحظة | التوصية |
|---|---|---|
| N-1 | «Education & Performance» يجمع مفهومين مختلفين تمامًا | إعادة التسمية إلى «Learn & Track» أو الفصل لاحقًا |
| N-2 | لا يوجد مدخل صريح للمنهجية (Methodology) | إضافة رابط «كيف نقيس الأداء؟» بجوار السجل مباشرة |
| N-3 | «My Previous Trades» قد يُفهم كتداول حقيقي | إضافة لفظ «محاكاة» في التسمية أو الوصف |
| N-4 | لا مدخل لحالة النظام | موجود في أسفل القائمة الجانبية (كافٍ) |
| N-5 | Ready Trades يجب أن يكون **الرابط الافتراضي** عند تسجيل الدخول لمستخدم عائد | تسهيل الوصول المباشر |

**التوصية النهائية:** الإبقاء على البنية الثمانية مع التعديلات N-1..N-5.
